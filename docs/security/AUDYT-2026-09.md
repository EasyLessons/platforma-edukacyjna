- Backend (`core/rate_limit.py`, PR #10): Redis `INCR`+`EXPIRE`, klucz per IP i opcjonalnie per pole body.
  Pokryte: `register` 5/10 min (`auth/router.py:56`), `verify_email` 10/10 min per `user_id` (`:75`),
  `resend_code` 3/10 min (`:94`), `login` 10/5 min per `login` (`:114`), `request_password_reset` 3/10 min (`:134`),
  `verify_reset_code` 10/10 min (`:152`), `reset_password` 5/10 min (`:170`), `google` 10/5 min (`:190`).
  Brak: `/refresh`, `/logout`, `PUT /users/me`, `/contact` (Next), wszystkie endpointy tablicy/uploadu.
- Wada strukturalna: IP za proxy (SEC-06). Przy błędzie Redis odpowiada 503 (fail-closed — dobrze).
- `/api/chat`: `src/_new/server/chat/rate-limit.ts` Map w pamięci procesu, 20/min + blokada 2 min
  (`config.ts:8-10`); `getClientIp` czyta `x-forwarded-for` (`:67-70`, poprawnie na Vercel). Na Vercel
  każda instancja/cold start ma własną mapę → limit „per instancja”, realnie N× większy; cache odpowiedzi
  (`response-cache.ts`) też per instancja. Docelowo: `@upstash/ratelimit` + istniejący Redis (Upstash REST)
  lub limit po `userId` w backendzie. Auth przed Gemini jest fail-closed (`auth.ts:13-14`) — dobrze.

### 3b. JWT / refresh

- Access: HS256 (`config.py:25`), `sub=user_id`, `exp` 15 min (`:27`), brak `iat/jti/typ` (`utils.py:26-31`).
  `.env.example` sugeruje 1440 min (SEC-23). Weryfikacja `jwt.decode(..., algorithms=[settings.algorithm])`
  (`dependencies.py:33-37`) — algorytm przypięty, `none` niemożliwe. `SECRET_KEY` wymagany, bez domyślnej.
- Refresh: 32 B `secrets.token_hex` (`utils.py:38-40`), w DB tylko SHA-256 (`:42-44`), 7 dni, rotacja przy
  każdym `/refresh` (`service.py:326-328`), `logout` unieważnia bieżący (`:341-351`). Brak: unieważnienia
  przy resecie hasła, detekcji reuse, „wyloguj wszędzie”, sprzątania wygasłych (SEC-11).
- Cookie: `HttpOnly`, `Secure`/`SameSite`/`Domain` z env (`router.py:30-41`), domyślnie `secure=False`,
  `samesite=lax`. Produkcyjne wartości: nie ustalono, sprawdzić na Render. `path="/"` — OK.
- Front: access token wyłącznie w pamięci (`tokenStore.ts:16-28`), dane usera (e-mail) w `localStorage`
  (`:33-57`) — niska waga; refresh w interceptorze z pojedynczym promise (`client.ts:61-113`) — poprawnie.
  `middleware.ts` nie weryfikuje tokenu (SEC-24).

### 3c. CORS

- FastAPI (`main.py:45-62`): lista + regex `*.vercel.app` z credentials (SEC-04); `allow_methods/headers=["*"]`.
  Handler 500 ręcznie dokleja CORS (`:150-154`) — spójny z regexem, więc dziedziczy problem.
- whiteboard-sync: Hocuspocus bez sprawdzania `Origin` (`index.ts:11-21`) — WebSocket nie podlega CORS, auth
  po tokenie (`auth.ts:34-41`) jest wystarczające; opcjonalnie `onConnect` z allowlistą `request.headers.origin`.

### 3d. Nagłówki bezpieczeństwa i propozycja CSP

Stan: patrz SEC-16. Hosty użyte w kodzie: własny origin, `NEXT_PUBLIC_API_URL` (backend), `*.supabase.co`
(REST + `wss://` Realtime + Storage obrazy), `NEXT_PUBLIC_WHITEBOARD_SYNC_URL` (wss Hocuspocus),
`accounts.google.com` (GSI: skrypt, iframe, connect), `lh3.googleusercontent.com` (zdjęcia Google),
`global.xirsys.net` (po SEC-05 tylko z serwera), `translate.google.com` + `translate.googleapis.com`
(widget; do decyzji — usunąć), `cdn.jsdelivr.net` (2 wystąpienia w `src`, sprawdzić: pdf.js worker/KaTeX),
`next/font/google` (fonty self-hosted przez Next — bez `fonts.gstatic.com`), `data:`/`blob:` (canvas, PDF, obrazy).

Do `next.config.ts` (zacząć od `Content-Security-Policy-Report-Only`, po tygodniu bez raportów przełączyć):

```
default-src 'self';
script-src 'self' 'unsafe-inline' https://accounts.google.com https://cdn.jsdelivr.net;
style-src 'self' 'unsafe-inline' https://accounts.google.com;
img-src 'self' data: blob: https://*.supabase.co https://lh3.googleusercontent.com;
font-src 'self' data:;
connect-src 'self' https://<API_HOST> https://*.supabase.co wss://*.supabase.co wss://<SYNC_HOST> https://accounts.google.com https://cdn.jsdelivr.net;
frame-src https://accounts.google.com;
worker-src 'self' blob:;
media-src 'self' blob:;
object-src 'none'; base-uri 'self'; form-action 'self'; frame-ancestors 'none'; upgrade-insecure-requests;
```

Uwagi: `'unsafe-inline'` w `script-src` jest wymagane przez `next/script` inline (`layout.tsx:44`) i GSI —
docelowo nonce przez `middleware.ts` (Next 16 wspiera `nonce` w `<Script>`). Jeśli widget Translate zostaje:
dopisać `https://translate.google.com https://translate.googleapis.com https://www.gstatic.com` do `script-src`,
`style-src`, `img-src`, `connect-src`. Dodatkowo: `Strict-Transport-Security: max-age=63072000; includeSubDomains; preload`,
`Permissions-Policy: microphone=(self), camera=(), geolocation=(), payment=()`, usunąć `X-XSS-Protection`.
FastAPI: `X-Content-Type-Options: nosniff`, `Cache-Control: no-store` na `/api/v1/auth/*`.

### 3e. Upload obrazów

  Front kompresuje do JPEG 1600 px (`image-compress.ts`), demo zablokowane (`:118-127`) — dobrze.
- Awatar: z przeglądarki prosto do `avatars` (SEC-03) — brak walidacji typu/rozmiaru, rozszerzenie z nazwy.
- `api/v1/assets/` to „zapisane zasoby” (JSON + miniatura SVG), nie pliki — SEC-07/15.

### 3j. Kanały Realtime — propozycja
